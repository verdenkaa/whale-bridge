# Форматы правок

Whale Bridge разбирает блоки кода на странице DeepSeek и превращает их в предложения.
Блок становится предложением только если его **первая строка** — комментарий с маркером
пути. Формат объясняется модели конструктором промпта (кнопка «⧗ Напомнить формат»
копирует короткую памятку в любой момент).

## Маркер пути

Первая строка блока — знак комментария языка файла, символ `&` и путь относительно
корня проекта:

```text
# &src/example.py          (Python, GDScript, YAML…)
// &src/main.js            (JavaScript, C#, C++, Java…)
<!-- &index.html -->       (HTML)
/* &src/main.cpp */        (блочный комментарий C-стиля)
-- &query.sql              (SQL, Lua, Haskell…)
```

Распознаются комментарии `#`, `//`, `--`, `;`, `%`, `'`, `REM`, `/* … */`,
`<!-- … -->`, `{- … -}`. Двойное экранирование из HTML (`&amp;`) тоже понимается.
Путь допускается обернуть в кавычки или бэктики — у файловых маркеров они срезаются
(у `&RUN:`/`&CMD:` — нет: там кавычки часть синтаксиса).

Проверки пути: только относительные, без `..`, без абсолютных путей, без `.git`,
без зарезервированных имён Windows, с защитой от выхода через символические ссылки.
Подробности — в [Модель безопасности](security.md).

Если модель написала путь вместе с именем корневой папки (`myproject/test.py`), а
такой подпапки в проекте нет, имя корня отбрасывается автоматически — карточка
помечается бейджем «путь исправлен».

## Полный файл

Для нового файла или файла, который переписывается почти целиком, после маркера идёт
полный текст без заглушек:

```text
# &src/example.py
print("Hello")
```

Для нового файла:

```text
# &NEW:src/example.py
print("Hello")
```

Ответы с заглушками («остальной код без изменений», `...`) распознаются эвристикой и
помечаются «возможно неполный код»: обычное применение блокируется, пока вы явно не
подтвердите его галочкой.

## REPLACE_BLOCK

Замена целой функции, метода или класса без передачи всего файла:

```text
# &src/example.py
<<<<<<< REPLACE_BLOCK
def main():
    print("new version")
>>>>>>> REPLACE_BLOCK
```

Приложение ищет блок в текущем файле:

1. точное совпадение первой строки (заголовка) — с учётом декораторов над ней;
2. если точного нет — поиск по имени функции/класса (`class|struct|enum|interface|
   trait|impl|namespace|module|object|record` или идентификатор перед `(`).

Границы тела определяются по стилю языка: отступ (Python) или парные фигурные скобки
с учётом строк, комментариев и экранирования. Совпало несколько мест — блок отклоняется
как неоднозначный с номерами строк; не найдено — приложение предлагает SEARCH/REPLACE
с соседними строками. Отступы заменяемого блока подгоняются под отступ заголовка в файле.

## SEARCH / REPLACE

Точечная правка:

```text
# &src/example.py
<<<<<<< SEARCH
old code
=======
new code
>>>>>>> REPLACE
```

Фрагмент SEARCH обязан встречаться в файле **ровно один раз**. Поиск идёт с уровнями
допуска, каждый следующий включается только если предыдущий не нашёл совпадений:

1. точное совпадение строк;
2. без учёта пробелов в конце строк;
3. без учёта отступов (разница отступов переносится и на строки REPLACE).

Неоднозначные и отсутствующие совпадения отклоняются — приложение не угадывает;
карточка показывает причину и номер строки. Несколько блоков SEARCH/REPLACE в одном
предложении применяются последовательно; ошибка в блоке останавливает остальные
(они помечаются «пропущен»), на диск не пишется ничего. Смешивать SEARCH/REPLACE
и полный текст файла в одном блоке нельзя.

## Удаление файла

```text
# &DELETE:src/old_file.py
```

Содержимое файла присылать не нужно. Удаление идёт в системную корзину с резервной
копией и откатом из «Истории».

## Перемещение файла

```text
# &MOVE:src/old_file.py -> src/new_file.py
```

Содержимое тоже не нужно. Целевой файл не перезаписывается: если он существует,
операция блокируется. Недостающие папки назначения создаются при явном подтверждении.
Журнал контекста переносится на новый путь: знание модели привязано к содержимому.

## Запуск файла (&RUN:)

```text
# &RUN:src/main.py --fast
5
hello
```

- Первая строка — маркер с путём и аргументами (аргументы разбираются с учётом
  двойных кавычек); путь проверяется так же строго, как у файловых маркеров
  (только внутри проекта).
- Тело блока — **ввод для программы**: по строке на каждое чтение `input()`. Пустое
  тело — ввода нет. Ввод можно раскрыть прямо в карточке и дописать свой в терминале.
- Если файла ещё нет на диске (модель предложила создать и сразу запустить, а создание
  вы ещё не приняли), запуск заблокирован подсказкой «Сначала примите предложение,
  создающее файл».
- После выполнения карточка показывает «Выполнено (код N)» и кнопку «↻ Повторить».

Поддерживаемые языки и планы запуска — в [Терминал и запуск](run.md).

## Команда терминала (&CMD:)

```text
# &CMD:grep -rn "class Player" src
```

- Карточка **«⌘ Команда»** показывает команду целиком и кнопку «▶ Выполнить»; команда
  выполняется в оболочке операционной системы (Windows — `cmd.exe /d /s /c`) в корне
  проекта. Кавычки в команде сохраняются, а консоль перед выполнением переводится в
  UTF-8 (`chcp 65001`).
- Команды делятся на три уровня риска: зелёный **«чтение»** (`grep`, `dir`, `type`,
  `findstr`), жёлтый **«осторожно»** (установка пакетов, скачивание, `taskkill`,
  `git commit`) и красный **«опасная команда»** (удаление, `git push`,
  `git reset --hard`, `format`, `reg add`, закодированные команды, флаги
  `--force`/`-rf`).
- Красный уровень показывает баннер с причинами и требует подтверждения «Я понимаю риск
  и хочу выполнить команду».
- Команды из блоков **без** маркера `&CMD:` по-прежнему просто показываются в чате и не
  выполняются.
- Выполненные и отклонённые предложения запоминаются: при прокрутке чата и догрузке
  старых сообщений они не всплывают заново.

Правила классификации (списки опасных команд, флагов и подкоманд git) — данные в
`src/runlangs.js`, общие для main и renderer: бейдж в карточке и требование
подтверждения не могут разойтись.

## Дедупликация и память решений

Отпечаток предложения — SHA-256 от (чат, операция, путь/команда, содержимое). Блок,
байт в байт совпадающий с уже применённым, отклонённым или снятым в этом чате
предложением, заново не предлагается. Это спасает от дублей, когда DeepSeek в режиме
рассуждений печатает тот же код до итогового ответа, и когда прокрутка старого чата
догружает давно отработанные блоки.

Блоки, появившиеся в первые 2.5 секунды после открытия чата или догруженные при
прокрутке, помечаются «из истории чата» и попадают в список только с галочкой
«Показывать код из истории чата».

## Запасной путь: «Взять из буфера»

Если вёрстка DeepSeek изменилась и наблюдатель DOM не работает (см. README, раздел
о смене веб-интерфейса), скопируйте ответ модели и нажмите **«Взять из буфера»** на
вкладке «Предложения»: приложение разберёт ```-блоки из буфера обмена тем же парсером.
