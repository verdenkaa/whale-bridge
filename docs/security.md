# Модель безопасности

Whale Bridge применяет изменения, сгенерированные ИИ, и делает это консервативно:
вывод модели считается **недоверенным вводом**, payload из renderer — тоже. Цель не
в том, чтобы автоматически сделать код ИИ правильным, а в том, чтобы сделать
**изменения файлов проверяемыми и обратимыми**.

## Единственный путь записи

Содержимое файлов проекта попадает на диск только через `fileops.applyChange` —
и предложения модели, и сохранение из редактора, и операции дерева (создать/
переименовать/удалить). Обойти этот путь в приложении некому. Каждый шаг:

1. **Проверка пути** (`paths.resolveInProject`):
   - только относительные пути, `..` запрещён, сегменты `.` отбрасываются;
   - абсолютные пути запрещены;
   - управляющие символы и `<>:"|?*` запрещены;
   - имена, заканчивающиеся точкой или пробелом, и зарезервированные имена Windows
     (`con`, `prn`, `aux`, `nul`, `com1`…`lpt9`) отклоняются;
   - любая часть пути `.git` запрещена;
   - результат обязан лежать внутри корня проекта (`path.relative`);
   - **защита от побега через символические ссылки**: realpath ближайшего
     существующего предка обязан лежать внутри realpath корня проекта.
2. **Проверка содержимого**:
   - перезапись файла с некорректным UTF-8 запрещена (иначе содержимое CP1251
     было бы молча повреждено);
   - операции проверяют ожидаемый SHA-256: `update`/`delete`/`move` не выполнятся,
     если файл изменился после формирования Diff;
   - `create` отказывается перезаписывать существующий файл;
   - `move` отказывается перезаписывать файл назначения;
   - эвристики неполного ответа и неоднозначные `SEARCH/REPLACE` блокируют
     применение до явного подтверждения пользователя.
3. **Резервная копия до записи**: `<opId>.before` / `<opId>.after` в `backups/`.
   Ошибка создания копии отменяет операцию.
4. **Атомарная запись**: временный файл (флаг `wx`, случайное имя `.aiws-…`),
   обратное чтение и сверка байтов, затем `rename` поверх цели. Перед самим
   rename хэш файла проверяется повторно — окно между чтением и записью не
   позволяет перезаписать чужую правку.
5. **Удаление — только в системную корзину** (`shell.trashItem`), плюс резервная
   копия: файл восстанавливается из «Истории» даже мимо корзины.
6. **Запись в историю** с источником (`ai` / `manual` / `rollback`); откат
   (`fileops.restore`) сверяет текущий хэш и без явного подтверждения не
   перезаписывает более новые правки.

Конфликт версий — полноправное состояние системы: сохранение из редактора при
изменённом на диске файле не пишет ничего и показывает три варианта (различия /
перезагрузить / сохранить поверх с отдельным подтверждением).

## IPC и изоляция процессов

- **Белые списки каналов** в `preload-ui.js`: `INVOKE`, `EVENTS`, `SEND`. Канала
  вне списка для renderer не существует. Соответствие списков реальным вызовам и
  обработчикам сверяется тестами (`wiring`, `ipc-channels`) как код, а не глазами.
- **Проверка отправителя**: каждый `ipcMain.handle` в main проверяет
  `event.sender === win.webContents` — страница DeepSeek не может вызвать
  привилегированный канал. `chat:blocks` принимается только от webContents чата и
  только если кадр принадлежит `deepseek.com`.
- **Санитизация payload**: всё, что приходит из renderer, чистится на входе
  (`cleanAiAccepts`, `sanitizeSections`, `sanitizeRunConfig`, `layoutMath.sanitize`,
  лимиты длин строк и размеров массивов) — renderer считается недоверенным
  источником структуры, а не только страница чата.
- **preload-chat.js** только читает DOM: не отправляет сообщения в чат, не
  вызывает API DeepSeek, не имеет доступа к привилегированным каналам UI.
- Окно интерфейса и чат — разные webContents с разными preload; интерфейс не
  имеет доступа к сессии чата, чат — к IPC интерфейса.

## Политика Electron

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` — у окна
  интерфейса, у чата и у popup-окон.
- CSP интерфейса: `default-src 'none'; script-src 'self'` (единственное ослабление —
  `style-src 'unsafe-inline'` для Monaco; обоснование — в `ui/index.html`).
  Monaco, xterm.js и шрифты грузятся локально из `node_modules`, без CDN.
- `will-navigate` окна интерфейса блокирует любую навигацию; чата — всё, кроме
  `http(s)`. Уровень приложения (`web-contents-created`) запрещает вторичным
  webContents (popup) открывать новые окна и навигировать на локальные схемы
  (`file://` и т.п.).
- Popup разрешены только для хостов авторизации (deepseek.com, google.com,
  gstatic.com, apple.com, microsoftonline.com, live.com), по `https:` и **в той же
  сессии** (`partition: persist:deepseek`) — иначе cookies входа не доходят до
  чата. Остальные ссылки уходят во внешний браузер через `shell.openExternal`
  (только `http(s)`).
- Разрешения страницы чата: request- и check-обработчики сессии разрешают только
  `clipboard-sanitized-write` и `fullscreen`. Камера, геолокация, чтение буфера
  обмена и прочие — запрещены.

## Исполняемые файлы и запуск

- `shell.openPath` («Открыть» в дереве) заблокирован для расширений, которые
  файловые ассоциации ОС **исполняют**: `.exe .bat .cmd .com .msi .msp .ps1 .vbs
  .vbe .js .jse .wsf .wsh .lnk .scr .sh .app .jar .reg .hta .py .pyw .rb .cpl .msc
  .pif .scf .url .inf .iso .img .appref-ms .chm .desktop .docm .xlsm .pptm`.
  Вместо открытия — показ в проводнике. Файл в проекте мог создать ИИ: запуск
  обязан быть явным действием (терминал, F5, карточка предложения), а не побочным
  эффектом двойного клика.
- **Ничего не запускается само.** Файл — только по нажатию «▶ Запустить» (путь
  проверяется на принадлежность проекту и существование). Команда `&CMD:` — только
  по нажатию «▶ Выполнить»; команда с красным уровнем риска показывает баннер с
  причинами и требует подтверждения «Я понимаю риск». Классификатор рисков — общие
  данные `src/runlangs.js` (см. [Терминал и запуск](run.md)).
- Процесс останавливается watchdog'ом бездействия, лимитом вывода (4 МБ) и кнопкой
  «■ Стоп» — вместе со всем деревом процессов. При выходе из приложения активная
  сессия убивается (`before-quit`).
- Ручной путь к инструменту побеждает автопоиск, но битый ручной путь — это честный
  отказ, а не молчаливая подмена инструмента из PATH.

## Данные и сеть

- У приложения **нет собственного сервера, учётных записей и телеметрии**. Всё
  состояние — локальные файлы в `userData` (config.json, history.json, backups/,
  context/, baselines.json).
- Сетевой трафик генерирует только встроенная страница DeepSeek (её же условия
  обслуживания к нему и применяются). Приложение не обходит аутентификацию,
  CAPTCHA или другие механизмы защиты сайта.
- Файлы проекта уходят в DeepSeek только вашими руками: промпт и «Скопировать
  файлы» кладут текст в буфер обмена, вставку и отправку в чат делаете вы.
  Приложение не вводит текст в поле сообщения скрытно.

## Проверки, которые стоит знать разработчику

- `resolveInProject` асинхронный и проверяет realpath: новая операция с файлом
  обязана идти через него, а не через конкатенацию путей.
- Проверка ожидаемого хэша делается **дважды** (до резервной копии и перед
  заменой файла) — не убирайте вторую: она закрывает гонку чтения-записи.
- Дедупликация предложений и память решений (applied/rejected/dismissed/
  executed) хранятся по отпечатку содержимого в `proposalDecisions` — это защита
  от «воскрешения» отработанных правок при догрузке истории чата.
- Добавляете IPC-канал — добавляйте его в белый список preload и в тесты wiring:
  канал вне белого списка не существует, а канал без обработчика роняет invoke.
