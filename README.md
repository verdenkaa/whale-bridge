## Что такое Whale Bridge?

Whale Bridge — это настольное приложение на Electron для разработчиков, которые используют **веб-интерфейс DeepSeek** при работе с локальным проектом.

Оно объединяет два инструмента в одном окне:

- **DeepSeek слева** — обычный веб-интерфейс, включая вашу учётную запись и чаты.
- **Whale Bridge справа** — дерево локального проекта, конструктор промптов, предлагаемые изменения, Diff, историю и инструменты отката.

Главная идея проста: **DeepSeek предлагает код, но Whale Bridge не записывает его на диск вслепую.**

Приложение разбирает поддерживаемые блоки кода на странице DeepSeek, сопоставляет их с локальными файлами, показывает получившийся Diff и применяет изменение только после вашего подтверждения.

### Что умеет

- Связывает веб-интерфейс DeepSeek с локальной папкой проекта.
- Раскладка лёгкой IDE: слева панель с вкладками «Файлы / Предложения / История»,
  в центре редактор Monaco, справа веб-чат DeepSeek.
- Конструктор промптов открывается в центре вместо редактора — одной кнопкой в шапке.
- Ширины панелей, активная вкладка и открытость «Промпта» запоминаются между запусками.
- Встроенный редактор кода на Monaco с деревом проекта, вкладками и подсветкой GDScript.
- Терминал внизу панели редактора (xterm.js ↔ node-pty): настоящий псевдотерминал с интерактивным вводом.
- Запуск активного файла на Python, JavaScript/TypeScript, C++, C и Java — кнопкой «▶ Запустить» или F5, с автопоиском инструментов в PATH.
- Отчёт о прогоне (файл, команда, ввод, вывод, код возврата) копируется в буфер одним нажатием — для вставки в чат.
- Ручные правки сохраняются через тот же безопасный путь, что и предложения ИИ, и попадают в историю как `manual`.
- Отслеживает, какую версию каждого файла знает модель, и подсвечивает файлы, о чьих изменениях чат не проинформирован.
- Собирает структурированный первый промпт из выбранных файлов проекта.
- Копирует выбранные файлы и их содержимое в буфер обмена для быстрой передачи контекста.
- Распознаёт изменения целых файлов и частичные правки `SEARCH / REPLACE` или `REPLACE_BLOCK`.
- Поддерживает создание, изменение, удаление и перемещение файлов через явные предложения.
- Показывает Diff до записи изменения.
- Проверяет файл на диске на наличие конфликтов с помощью SHA-256.
- Создаёт резервные копии и хранит историю операций.
- Поддерживает откат изменений.
- Защищает от небезопасных путей, выхода через символические ссылки и ряда распространённых некорректных ответов ИИ.
- Отказывается перезаписывать существующие файлы с некорректной UTF-8-кодировкой, не допуская их незаметного повреждения.

Whale Bridge **не имеет собственной ИИ-модели или бэкенда**. Он работает с уже открытым в приложении веб-сервисом DeepSeek.

## Быстрый старт — Windows

### Вариант 1: скачать готовую сборку

Скачайте одну из сборок для Windows со страницы **Releases** репозитория:

- **Installer** — обычная установка Windows с ярлыками в меню «Пуск» и на рабочем столе.
- **Portable** — автономный исполняемый файл, не требующий установки.

Запустите Whale Bridge и войдите в DeepSeek в правой панели. Её ширина тянется разделителем
и запоминается между запусками.

### Вариант 2: запуск из исходников

Требования:

- Windows, Linux or macOS
- Node.js 20+
- npm

Then:

```bash
npm install
npm start
```

В Windows файл `start.bat` может автоматически установить зависимости и запустить приложение.

Для Linux/macOS:

```bash
./start.sh
```

## Как пользоваться

### 1. Откройте DeepSeek

Запустите Whale Bridge и войдите в свою учётную запись DeepSeek в левом веб-представлении.

Whale Bridge не создаёт и не управляет вашей учётной записью DeepSeek. Он лишь отображает веб-интерфейс DeepSeek внутри приложения.

### 2. Добавьте проект

В верхней панели нажмите **Добавить папку** и выберите корневую папку проекта.

Выбранный проект связывается с текущим чатом DeepSeek. Эта связь сохраняется локально, поэтому позже можно вернуться к тому же чату.

### 3. Подготовьте первый промпт

Нажмите **Промпт** в шапке — конструктор откроется в центральной панели вместо редактора кода.
Кнопка сменит подпись на **Редактор кода**, а повторное нажатие (или крестик **✕**) вернёт редактор.

Конструктор промпта может включать:

- задачу;
- контекст проекта;
- выбранные файлы и папки;
- структуру проекта;
- ограничения;
- правила работы;
- желаемый режим работы.

Выберите файлы, которые должен видеть DeepSeek, и нажмите **Скопировать промпт**. Вставьте сгенерированный промпт в DeepSeek самостоятельно.

Также можно использовать **Скопировать файлы**, чтобы поместить выбранные файлы и их содержимое в буфер обмена одним компактным блоком контекста.

> Whale Bridge **не вводит текст скрытно** в поле сообщения DeepSeek и не отправляет сообщения от вашего имени. Вы сами решаете, что вставлять и отправлять.

### 4. Попросите DeepSeek изменить проект

Попросите DeepSeek изменить выбранные файлы в соответствии с правилами из сгенерированного промпта.

Whale Bridge отслеживает отображаемый ответ DeepSeek. Поддерживаемые маркеры кода указывают, какому локальному файлу принадлежит блок кода.

For example:

```text
# &src/example.js
```

or for a new file:

```text
# &NEW:src/example.js
```

После завершения ответа Whale Bridge создаёт предложение: карточку на вкладке **Предложения**
и синюю точку рядом с файлом в дереве. Пока предложения не рассмотрены, счётчик виден
и на вкладке **Файлы** — его не получится пропустить, работая в дереве.

### 5. Проверьте Diff

Клик по карточке предложения (или по синей точке у файла в дереве) открывает в центральной
панели **Monaco DiffEditor** вместо редактора.

Слева — ваш файл таким, какой он сейчас (буфер редактора или диск). Справа — **живой
предпросмотр результата**: то, что окажется в файле после принятия отмеченных изменений.
Переключатель в строке действий меняет сравнение на «версия модели → предложение».

#### Принятие по частям

Под строкой действий — список **ханков**: отдельных правок модели с номерами строк,
счётчиками `+`/`−` и первой изменённой строкой. Снимите галочки с того, что не нужно, —
предпросмотр справа пересчитается сразу.

- **Принять все (N) в буфер** / **Принять выбранные (K/N)** — изменения попадают
  **в буфер редактора**, файл становится несохранённым (`●` во вкладке). На диск они
  уйдут только по `Ctrl+S` — тем же путём, что и ваши собственные правки. Отменить
  принятие можно `Ctrl+Z`, пока файл не сохранён;
- **Принять и сохранить** — то же самое плюс немедленная запись на диск;
- **Отклонить** — закрыть предложение, ничего не меняя.

Пока принятое не сохранено, карточка предложения помечена **«в буфере редактора»**,
а в строке состояния открытого файла — бейдж **«принято от модели»**. Если закрыть
вкладку без сохранения или перечитать файл с диска, принятое теряется, а предложение
снова становится доступным — оно закрывается только фактической записью на диск.

#### Ваши правки не теряются

Принятие **трёхстороннее**: база — версия, которую видела модель (снимок из журнала
контекста; если снимка нет, но файл с тех пор не менялся, базой служит диск), «ваше» —
текущий буфер, «их» — выбранные ханки. Правка в другом месте файла сохраняется вместе
с правкой модели. Если вы изменили **те же строки**, слияние не выполняется: показывается
конфликт с обеими сторонами, а ни диск, ни буфер не меняются.

Когда база слияния недоступна (снимка нет, а файл менялся), частичное принятие честно
запрещается — остаётся «Принять целиком (перезаписать файл)» с предупреждением.

Создание и удаление файла в буфере невыразимы, поэтому остаются прямыми операциями
на диске: **Создать файл** / **Удалить в корзину** (с подтверждением и резервной копией).

#### Предупреждения

Строки над диффом показывают то, что важно до принятия: ответ похож на неполный (обычное
применение заблокировано, пока вы не отметите «Я проверил(а) Diff и всё равно хочу
применить»), результат каждого блока `SEARCH/REPLACE`, исправленный путь, создание папок,
изменение файла после того, как модель его видела.

Отдельного режима «Подробности» больше нет — он дублировал дифф. Текстовый отчёт
остаётся запасным выходом: просмотр уходит в него сам, если Monaco не поднялся или если
диффа физически нет (перемещение файла, ошибка пути, не применимый блок правки).

Тот же дифф открывается для операции из **Истории** (до/после) и для **моих правок**
(версия модели → текущий файл).

Сам факт генерации кода DeepSeek ничего не записывает в проект. Нажимайте принятие
только после проверки результата.

### 6. Отмените изменения

Каждая применённая операция записывается в историю и, где это возможно, защищается резервной копией.

Используйте **↩** рядом с файлом в дереве (кнопка видна при наведении на строку) или вкладку **История**,
чтобы посмотреть предыдущие операции и откатить их.

Откат сам записывается в историю, но **неоткатим**: резервные копии для него не создаются,
чтобы не удваивать их число. На один файл хранится не более двух таких записей.

### 7. Панели и раскладка

Окно делится на три колонки, каждая тянется своим разделителем:

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 🐋 Whale Bridge  чат · проект       [Промпт] [⧗ Напомнить формат]     │
├────────────────┬──┬──────────────────────────────┬──┬────────────────┤
│ Файлы |        │↔ │ вкладки открытых файлов      │↔ │                │
│ Предложения |  │  │                              │  │    DeepSeek    │
│ История        │  │   редактор Monaco            │  │    (веб-чат)   │
│                │  │   / «Промпт»                 │  │                │
│ дерево проекта │  │   / просмотр предложения     │  │                │
│ или список     │  │   строка состояния           │  │                │
└────────────────┴──┴──────────────────────────────┴──┴────────────────┘
```

- **Левая панель** — вкладки «Файлы», «Предложения» и «История»: дерево проекта,
  карточки предложений и журнал операций живут в одной колонке и переключаются.
  Счётчик нерассмотренных предложений показывается и на вкладке «Файлы».
- **Центральная панель** показывает ровно одно из трёх: код (Monaco), конструктор
  «Промпт» или просмотр (Diff предложения, операция истории, «мои правки», конфликт).
  Кнопка **Промпт** в шапке меняет подпись на **Редактор кода** и обратно; крестик **✕**
  в панели промпта закрывает его совсем. Открытие файла из дерева тоже возвращает редактор.

  Переключения помнят прежнее окно: просмотр, открытый поверх «Промпта», не закрывает
  форму — после «← К списку» набранный промпт остаётся на месте. Кнопка в шапке при
  открытом просмотре подписана «← Просмотр» и возвращает именно к нему.
- **Чат DeepSeek всегда справа.** Переноса на другую сторону нет: перестановка колонок
  ломала отрисовку нативного `WebContentsView`, поэтому сторона зафиксирована.
- Ширины панелей, активная вкладка и открытость «Промпта» сохраняются между запусками.
- **⧗ Напомнить формат** в шапке копирует памятку о маркерах и формате кода в любой момент.

Геометрию считает интерфейс, а не главный процесс: пустой контейнер на месте чата
измеряется `ResizeObserver`, и полученный прямоугольник уходит в main, который кладёт
туда `WebContentsView` с DeepSeek.

### 8. Правьте файлы во встроенном редакторе

Центральная панель — локальный редактор кода на Monaco: вкладки открытых файлов сверху,
строка состояния снизу. Дерево проекта живёт на вкладке **Файлы** слева — все действия
по файлу собраны в строках дерева.

- Откройте файл кликом в дереве или через **Ctrl+P** (поиск по имени).
- **Ctrl+S** сохраняет файл.

Отметки в дереве и на вкладках (одна цветовая схема на всё приложение):

| отметка | смысл |
|---|---|
| `●` оранжевая | несохранённые изменения в редакторе |
| `⚠` красная | файл изменён вне редактора — сохранение потребует решения |
| `◆` янтарная | модель в чате не знает текущую версию (клик открывает сравнение) |
| синяя точка | есть предложение модели (клик открывает предложение) |
| `↩` при наведении | откатить последнюю операцию файла |
| `↗` при наведении | показать файл в проводнике |

Сохранение защищено так же, как применение предложения ИИ: файл проверяется по SHA-256,
создаётся резервная копия, запись атомарная. В историю операция попадает с источником
`manual`, поэтому приложение отличает вашу правку от правки модели и позволяет откатить её
тем же **↩ Откатить**.

Если файл изменился на диске, пока вы его редактировали, **Ctrl+S ничего не запишет** и
предложит три варианта:

- **Показать различия** — версия на диске рядом с вашим буфером;
- **Перезагрузить файл** — перечитать с диска, ваши правки будут потеряны;
- **Сохранить поверх** — перезаписать диск вашей версией. Эта кнопка намеренно не основная
  и требует отдельного подтверждения: чужие изменения будут потеряны безвозвратно.

#### Горячие клавиши

| сочетание | действие |
|---|---|
| `Ctrl+S` | сохранить файл |
| `Ctrl+P` | поиск файла по имени |
| `Ctrl+F` | поиск в файле (Monaco) |
| `Ctrl+W` | закрыть вкладку |
| `Ctrl+Tab` | следующая вкладка |
| `Alt+←` / `Alt+→` | предыдущая/следующая вкладка |
| `F12` | DevTools панели DeepSeek |
| `Ctrl+Shift+I` | DevTools интерфейса Whale Bridge |

Клавиши работают, когда фокус в интерфейсе Whale Bridge. Если фокус в панели DeepSeek,
клавиатура уходит странице DeepSeek — это ограничение встраивания веб-интерфейса, поэтому
`F12` и `Ctrl+Shift+I` вынесены в меню Electron и работают всегда.

`Ctrl+Shift+S` (Save As) пока не реализован.

### 9. Что знает модель

Файл меняется не только через Whale Bridge: его правите вы в другом редакторе или в нашем,
восстанавливает откат, трогает сборка или система контроля версий. В этот момент модель
продолжает считать актуальной ту версию, которую видела раньше, и предлагает правки от
устаревшего кода — блоки `SEARCH` перестают находиться, а автоправки ломаются.

Поэтому приложение ведёт **журнал контекста**: какую версию какого файла знает модель
в текущем чате. Расхождение — это несовпадение того, что сейчас на диске, с последней
версией, которую модель видела.

Модель считает знающей версию, когда:

- вы **применили её предложение** — содержимое получено от неё (для перемещения файла
  отмечается новый путь);
- вы **сохранили из редактора ровно её текст**: приняли предложение целиком и не смешали
  с другими правками (сравнение побайтовое, переводы строк не учитываются);
- файл ушёл ей как контекст через **«Скопировать файлы»** в конструкторе промпта;
- вы **подтвердили вручную** — «✓ Модель проинформирована».

Приняли только часть ханков или добавили к ним свои правки — отметка **не** ставится:
получившийся файл модель никогда не видела, и он подсвечивается ◆ как расхождение.
Само предложение при этом закрывается (оно обработано), а запись в истории получает
источник «предложение модели» с пометкой, сколько ханков было принято.

**«Скопировать актуальные версии для модели» предупреждения не снимает**: скопировать
в буфер — не значит отправить в чат, а ложное «модель знает» хуже заметного, потому что
скрывает уехавший контекст. Отметку ставит только явное действие.

Отметка хранится как SHA-256 содержимого, а не как флаг. Отсюда два свойства: следующее
изменение файла снимает её само, и её нельзя «забыть» снять — она привязана к содержимому,
а не к действию пользователя.

Журнал привязан к **чату**, а не к папке: в одном проекте может быть несколько чатов,
и в каждом модель знает своё. Журнал хранится в конфигурации и **переживает перезапуск** —
учёт контекста, который обнуляется вместе с сессией, смысла не имеет.

Файл, которого в журнале нет, расхождением не считается: модель его никогда не видела,
и сравнивать не с чем. Иначе подсвечивался бы весь проект и отметка обесценилась бы.

#### Где это видно

| место | отметка |
|---|---|
| дерево файлов и вкладки редактора | `◆` — модель не знает текущую версию |
| строка состояния редактора | бейдж «модель не знает» и кнопка «✓ Модель знает» |
| вкладка **Файлы**, шапка и плашка | кнопки «Скопировать для модели» и «✓ Модель знает все», список расхождений |
| карточка предложения | бейдж «изменён вручную» и предупреждение в Diff |

Клик по `◆` в дереве открывает сравнение последней известной модели версии с текущим файлом.

#### Старые ответы модели

При прокрутке чата вверх DeepSeek догружает старые сообщения, и их блоки кода раньше
предлагались как свежие правки. Теперь приложение помнит, какие блоки уже разбирало
в этом чате, и такие предложения попадают в раздел «Показывать код из истории чата»,
а не в основной список.

#### Сравнение с версией модели

Клик по `◆` показывает, что именно изменилось: слева версия, которую видела
модель, справа текущий файл. Для этого журнал хранит не только хэш, но и **снимок
содержимого** — в `context/` рядом с резервными копиями, адресуемый по хэшу, поэтому
одинаковое содержимое разных файлов хранится один раз.

Снимок не сохраняется для версий больше ~1 МБ текста, и всего их хранится не больше 300:
вытесняются только те, на которые журнал больше не ссылается. Если снимка нет, сравнение
строится от резервной копии последней операции, и это оговаривается явно.

### 10. Терминал и запуск файлов

Внизу панели редактора открывается **терминал** — настоящая псевдоконсоль (xterm.js
в интерфейсе, node-pty в главном процессе): с интерактивным вводом, потоковым выводом
и честным кодом возврата. Панель независима от режимов центра: терминал виден и когда
открыт код, и когда открыт просмотр предложения или «Промпт». На чат панель не наезжает
никогда — чат занимает свою колонку на полную высоту.

- **Ctrl+`** или кнопка «Терминал» в шапке — показать/скрыть панель.
- Высота панели перетаскивается за разделитель и запоминается между запусками.
- **✕** на панели — остановить процесс (если идёт) и скрыть терминал.
- Каждый новый запуск начинается **с чистого экрана**: предыдущий вывод не смешивается
  с новым (в том числе когда прошлая программа закончила строку без перевода). История
  прогона при этом не теряется — она копируется в буфер кнопкой «📋 Отчёт».

#### Запуск активного файла

Кнопка **«▶ Запустить»** в строке вкладок редактора или **F5** выполняет активный файл
в папке проекта. Перед запуском все несохранённые буферы сохраняются тем же единственным
путём записи, что и всегда (`file:write`): программа запускается ровно с тем кодом,
который вы видите.

| язык | расширения | как запускается |
|---|---|---|
| Python | `.py` | `python -u файл` (кандидаты PATH: `python`, `python3`, `py`; предпочитается Python 3) |
| JavaScript | `.js` `.mjs` `.cjs` | `node файл` |
| TypeScript | `.ts` `.mts` | `node --experimental-strip-types файл` (нужен Node.js 22 или новее) |
| C++ | `.cpp` `.cc` `.cxx` | `g++ файл -o .ide_build/имя` → `.ide_build/имя` (кандидаты: `g++`, `clang++`) |
| C | `.c` | `gcc файл -o .ide_build/имя` → `.ide_build/имя` (кандидаты: `gcc`, `clang`) |
| Java | `.java` | `javac -encoding UTF-8 -d .ide_build/classes файл` → `java -cp .ide_build/classes класс` |

- Инструменты ищутся в PATH автоматически; если инструмент не найден, терминал и тост
  объясняют, что установить или где указать путь вручную.
- Компилируемые языки идут в одном терминале двумя шагами: компиляция → разделитель
  `── запуск ──` → выполнение бинарника. Провал компиляции останавливает сессию.
- Артефакты сборки складываются в скрытую папку `.ide_build/` внутри проекта — дерево
  файлов и промпт-генератор её не видят, байт-код и бинарники не мусорят рядом с исходниками.
- Код возврата показывается в строке состояния терминала: `0` — зелёным, иное — красным.

#### Остановка и безопасность

- **■ Стоп** убивает всё дерево процессов (на Windows — `taskkill /T /F`, на POSIX —
  сигнал группе процессов): скрипт с дочерними процессами не оставляет сирот.
- Новый запуск при работающем процессе = перезапуск: предыдущий останавливается автоматически.
- Watchdog бездействия: если процесс молчит 600 секунд (не печатает и не читает ввод),
  он останавливается с пометкой в терминале.
- Вывод больше 4 МБ останавливает процесс — терминал и память не переполняются.
- На время сессии наблюдение за папкой проекта приостанавливается: компиляция не
  заставляет дерево файлов мигать.
- Запуск **не трогает** журнал контекста и историю операций: это чтение мира, а не
  изменение проекта. Единственная запись на диск — папка `.ide_build/`.
- Ничего не запускается само: любая сессия — результат вашего нажатия кнопки.

#### Отчёт для чата

**📋 Отчёт** копирует в буфер обмена весь прогон — файл, команду, папку проекта,
код возврата, ввод и вывод (ANSI-коды терминала вычищаются, длинный вывод обрезается
до хвоста ~200 КБ). Вставьте отчёт в чат DeepSeek — модель увидит результат прогона
в читаемом виде.

- В строке «Команда» инструмент показывается коротким именем (`python -u test.py`,
  `javac … → java -cp .ide_build/classes Main`), а не полным путём из PATH: полный путь
  виден в настройках запуска, а в чате он только шумит.
- Ввод показывается построчно, как вы его набирали; служебные последовательности
  терминала (уведомления о фокусе, стрелки, Backspace) в отчёт не попадают.

#### Горячие клавиши запуска

| сочетание | действие |
|---|---|
| `F5` | запустить активный файл |
| `` Ctrl+` `` | показать/скрыть терминал |

Сочетания работают, когда фокус не внутри редактора Monaco (Monaco перехватывает
клавиатуру, когда курсор в коде) — кликом по кнопке можно запустить всегда.

## Поддерживаемые форматы правок

### Полный файл

Для полного файла DeepSeek может вернуть содержимое под маркером его пути:

```text
# &src/example.py
print("Hello")
```

Для нового файла:

```text
# &NEW:src/example.py
print("Hello")
```

### REPLACE_BLOCK

Используйте этот формат для замены целой функции, метода или класса без передачи всего файла:

```text
# &src/example.py
<<<<<<< REPLACE_BLOCK
def main():
    print("new version")
>>>>>>> REPLACE_BLOCK
```

Whale Bridge находит соответствующую функцию/метод/класс в текущем файле и заменяет этот блок.

### SEARCH / REPLACE

Используйте этот формат для небольшой точечной правки:

```text
# &src/example.py
<<<<<<< SEARCH
old code
=======
new code
>>>>>>> REPLACE
```

Искомый текст должен точно соответствовать одному месту в файле. Неоднозначные или отсутствующие совпадения отклоняются — приложение не пытается угадывать.

### Удаление файла

```text
# &DELETE:src/old_file.py
```

### Перемещение файла

```text
# &MOVE:src/old_file.py -> src/new_file.py
```

Для операций удаления и перемещения не требуется перезаписывать содержимое файла.

## Модель безопасности

При применении изменений, сгенерированных ИИ, Whale Bridge намеренно действует консервативно.

Перед записью файла он проверяет, среди прочего:

- path traversal such as `..`;
- absolute paths;
- attempts to escape through symlinks;
- `.git` and other protected paths;
- valid operation type (`create`, `update`, `delete`, `move`);
- SHA-256 conflict between the file used to build the proposal and the current file on disk;
- incomplete or obviously truncated AI responses;
- ambiguous `SEARCH / REPLACE` matches;
- invalid UTF-8 when an existing file would be rewritten.

Там, где это уместно, запись выполняется через резервную копию, временный файл и атомарную замену.

Цель не в том, чтобы автоматически сделать код, сгенерированный ИИ, правильным. Цель — сделать **изменения файлов с помощью ИИ проверяемыми и обратимыми**.
